            def run_tests():
                ...

            if __name__ == "__main__":
                run_tests()

Чому в консолі був “порожній вивід”
    Причини:
    код виконувався в Pyodide, але ми не перехопили stdout.
    Треба зробити:

        import sys
        from io import StringIO

        buffer = StringIO()
        sys.stdout = buffer

    А потім в JS:
        pyodide.runPython("buffer.getvalue()")

    Додамо це в tester.py.

🔷 Рівні складності:
    Easy / Medium / Hard
    
    План реалізації з рівнями, розподіл завдань, приклади задач і правила підрахунку прогресу:

    1. Як рівні відображаються в UI
        Селектор рівня (вгорі): кнопки Easy | Medium | Hard. За замовчуванням відкривається Easy.
        Коли користувач обирає рівень — у списку показуються тільки задачі цього рівня.
        Для кожної задачі: назва, короткий опис, старт-код, кнопки Запустити, Перевірити, Скинути до початкового, Зберегти чернетку.
        Прогрес показується глобально (усі пройдені задачі / загальна кількість) у відсотках (ціле число).

    2. Прогрес і збереження
        Прогрес = round( (кількість задач з прапорцем "пройдено") / (загальна кількість задач) *100 ).
        Локальне збереження за допомогою localStorage:
        Збережені чернетки коду для кожної задачі.
        Статус пройдено/не пройдено.
        Вибрана тема редактора.
        Кнопка «Скинути код» відновлює стартовий код для поточної задачі (не чіпає інші).
        При зміні рівня — прогрес лишається глобальним (сумарний).

    3. Формат задач в tasks.json
    Кожна задача матиме такі поля:
    { 
          "id": "T32", 
          "lesson_id": "L08", 
          "title": "Dict Comprehension", 
          "level": "hard", 
          "text": "Створіть словник, де ключі — це числа від 1 до 3, а значення — це їхні куби, використовуючи dict comprehension.", 
          "starter": "#...to autocomplete command press ctrl+space...\nresult = { # ... }\nprint(result)", 
          "hint": "Синтаксис: `{ключ: значення for елемент in послідовність}`. \n Приклад: {x: x*2 for x in range(3)}\nРезультат: {0: 0, 1: 2, 2: 4}", 
          "solution": "result = {x: x**3 for x in range(1, 4)}\nprint(result)", 
          "tests": [ { "input": "", "output": "{1: 1, 2: 8, 3: 27}" } ] 
    },

    Підтримувані типи тестів: stdout_equals, stdout_contains, function_return, assert_eval (рядок коду, 
        який виконується в середовищі тестера).

    4. Приклади задач (по 2 на рівень)
        Easy
        Hello — вивести Hello
        Тестер: stdout_equals "Hello\n"
        Sum two numbers — зчитати два числа і вивести суму
        Тестер: викликати код з input 2\n3\n і перевірити stdout_equals "5\n"

        Medium
        List manipulations — повернути відсортований список у вигляді рядка
        Тестер: assert_eval — викликати функцію користувача з даними і порівняти
        Файлові рядки — прочитати текст (через stdin) і порахувати частоту слів

        Hard
        Class & inheritance — реалізувати клас з методами, перевірити поведінку успадкування
        Generator pipeline — написати генератор, який фільтрує великі потоки і повертає агрегат

    5. Автотести: як працюють
        JS передає код користувача та поточний тест (з tasks.json) до Pyodide.
        У середовищі Pyodide запускається tester.py (окремий модуль), який робить:
        ізоляцію виконання (без доступу до DOM),
        перехоплення stdout (через io.StringIO),
        виконання коду користувача,
        запуск перевірок з tests (із tasks.json),
        повернення JSON: { ok: true/false, message: "...", output: "..." }.
        JS відображає результат у вікні консолі, показує гумористичне повідомлення якщо успіх.

У цій збірці (згідно з наданими файлами app.js та index.html)
всі перелічені дані зберігаються локально у браузері користувача за допомогою об'єкта localStorage.
Зберігання даних відбувається за певними ключами:
    1. Місце зберігання даних у localStorage:
        Тип даних: Прогрес, Статус задач (пройдено/ні), Чернетки коду, Використання підказок.
        Ключ localStorage: 'pyTrainerProgress'
        Місце обробки в app.js: Функції loadProgress(), saveProgress(), saveCode(), onCheck()

        Тип даних: Вибрана тема редактора
        Ключ localStorage: 'theme'
        Місце обробки в app.js: Глобальна змінна CODE_MIRROR_THEME, функції initThemeToggle(), loadProgress()
        
        Тип даних: Остання відкрита задача
        Ключ localStorage: 'lastTaskId'
        Місце обробки в app.js: Функція bootstrap()

    2. Як це реалізовано в app.jsA. Прогрес та чернетки коду (pyTrainerProgress)
    Весь прогрес користувача зберігається в одній глобальній змінній USER_PROGRESS (це об'єкт/словник у JavaScript), 
    яка потім серіалізується у формат JSON і зберігається під ключем 'pyTrainerProgress'.

    Завантаження (loadProgress):
        JavaScript
        function loadProgress() {
            try {
                const savedProgress = localStorage.getItem('pyTrainerProgress');
                if (savedProgress) {
                    USER_PROGRESS = JSON.parse(savedProgress);
                }
            // ...
        }

    Збереження (saveProgress / saveCode):
        JavaScript
        // (приблизна логіка, використовується при запуску/перевірці)
        function saveProgress() {
            localStorage.setItem('pyTrainerProgress', JSON.stringify(USER_PROGRESS));
        }

    Об'єкт USER_PROGRESS має структуру приблизно такого вигляду:
        JavaScript
        // Приклад вмісту USER_PROGRESS:
        {
          "T1": {
            "code": "print('Привіт!')",
            "done": true,      // Статус пройдено
            "hintUsed": false
          },
          "T2": {
            "code": "a=1",
            "done": false,
            "hintUsed": true
          }
        }
